## 已验证的主要原因

模拟器先把传染损失加给债权节点，然后只有当该节点 TVL > 0 时才把累计损失限制到它的 TVL。TVL 恰好为 0 时不限制，但该节点也不会进入新增传播队列。结果是 0 与极小正数触发不同的损失统计。

独立两节点自检：债务节点 TVL=100、冲击 50%，只有一个债权节点。债权节点 TVL=0 时，旧模拟器系统损失为 100%；将其改为 0.000001，损失约为 50%。这不是市场变化，是计算分支产生的跳变。

真实例子：h1 的 2025-01-06→2025-01-13 图有 10,977 个共同节点，其中 6,503 个未来 TVL 为零，2,526 个被模型预测为正数。WBTC 当前/未来 TVL 都是 0，预测为 0.00434883；WETH 当前/未来 TVL 都是 0，预测为 0.04852424。这些数值来自保存的 NPZ，不是新推理。零在原数据中表示真实零还是缺失/非协议节点，当前证据不能一概确定。

## 固定冲击对象的替换实验

全部网络用共同节点集。所有版本使用原预测选出的同一冲击对象、同一冲击比例、原模拟器。误差单位为系统损失百分点，越小越好。以下替换均为诊断，不是新的正式模型成绩。

| Horizon | 原预测 MAE | 仅保持当前零 TVL 节点为零 | 所有节点改为真实 TVL（使用未来答案） | 所有边改为真实边及金额（使用未来答案） |
|---|---:|---:|---:|---:|
| h1 | 5.896 | 1.214 | 0.958 | 5.694 |
| h4 | 6.960 | 1.413 | 0.966 | 7.165 |
| h8 | 6.904 | 1.409 | 0.768 | 7.268 |
| h12 | 5.182 | 1.913 | 1.186 | 4.675 |

h4 只保留当前零 TVL 状态，MAE 减少约 79.7%；替换全部真实边并没有解决差距。这支持零 TVL 分支与节点预测的交互是当前误差的主要来源，不能据此说模型全部误差都由该分支造成。

当前零 TVL 节点在未来可能真的增长，所以“强制保持零”不是已经验证的部署修复。这个替换只用于定位问题。

## 其他发现与排除项

- 原预测与真实网络的 321 个损失值逐一复现先前审计，容差 1e-9 百分点；完整真值替换的误差为 0。Python 哈希种子固定为 0。
- 使用训练包内冻结源码核对。训练核心当前文件 SHA-256=d2e47cb6ce33aff1d8c1ecba0de3494f84c3596ee1cefb45e9e29825b2be4a0e；Task II 评估器 SHA-256=3a55c4384163ed7a4b9d555f7da8c72c08915cb5b2a114cb451c10e0f1692409，均与冻结包逐字节相同。
- 边金额在保存预测前只加了一次历史基线，重建时只执行一次 expm1；没有发现重复加基线或重复指数还原。原先审计已将目标边集、金额与原始未来快照交叉核对。
- 删除假阳性边或替换全部真实边都没有消除 Table 4 的大误差，所以不能把假阳性边认定为本次压力测试差距的主要原因。
- 边金额的线性尺度仍有独立的严重长尾问题。跨所有时间点累加预测/真实边总金额的比值，h1/h4/h8/h12 分别为 13341.825/42910.077/2911.759/275.777。这个统计重复计入不同预测时间点，不是某一时点系统敞口，也不是 Table 4 的误差分解。
- 例如 h1 第一张图的 2196→1599 边，预测约 1.226e14，真实约 5.381e6。这条是真实存在的边，不是假阳性。对数均值可能掩盖少数线性金额极大的错误；该问题需要另行检查，不能因零 TVL 诊断成功就忽略。
- Table 4 模拟器按每个债务节点的相对入边份额分配损失，因此绝对金额夸大与压力测试误差并不一一对应。
- 候选图使用保存的真实正边与 5:1 采样负边，非全节点对推理。这沿用原评估路径，不能外推为全图部署表现。

## 与论文结果的证据边界

这次定位的是“当前 run 为什么在现有模拟器上出现较大的损失误差”。论文原始 Task II 逐周预测、原始运行命令及 checkpoint→Table 4 的映射尚未恢复，不能证明原论文具体哪次运行或哪种零值预测产生了印刷数值。保留零值后的数值也没有逐项等于论文，不能称为 Table 4 已复现。
